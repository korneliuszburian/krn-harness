## Current Decision

v0.1 product value is now:

```txt
krn run -> run-result -> run-bundle -> report/release-check as supporting evidence
```

Dashboard-lite, MCP, vector retrieval, autonomous subagents, protected-data
workflows, and package publishing remain intentionally unbuilt.

## Open Proof Gaps

- Adoption friction hardening from `docs/product/adoption-friction-register.md`
  now has Stage 9 wrapper-first target evidence; continue to harden one recorded adoption friction at a time and keep measuring whether wrapper count/noise becomes a durable adoption cost.
- Stage 10 follow-up hardening: target-run release-check/report noise,
  context over-inclusion risk, and Python wrapper/config overhead. The approved
  Stage 10 comparison is local evidence only and must not be overclaimed.
- Governed memory usefulness beyond context recall; one approved wrapper-first
  validation memory surfaced as reference-only context with opt-out proof and
  informed Stage 9 wrapper-first validation, but Stage 10 recorded no target
  memory items, so target-workflow outcome impact remains unproven.
- Real non-bypass Codex hook loading/trust.
- Noisy large repo context behavior.
- Production WordPress/ACF behavior.
- Reviewer usefulness beyond deterministic local records.
- Operator summary usefulness beyond first deterministic artifact.
- UI-facing visual proof on an approved target; `visualProof` metadata is only a
  contract lane until a target run supplies actual evidence.
- Remote CI has a workflow file, but a current remote run is not local proof until checked in GitHub.
